EraInfra

EraInfra is a self-hosted CI fleet for GitHub Actions. It runs each job in a fresh, isolated environment on Linux, Mac and Windows machines you already own, then destroys it. Machines connect out to the control plane, so none of them needs a public IP.

Who it is for

Teams and individuals with spare hardware, such as a home server, a Mac mini or office machines, who want to run CI on it without giving every job a long-lived host. A workflow changes one line:

jobs:
  test:
    # was: runs-on: ubuntu-latest
    runs-on: rc-linux-js

rc-linux-js is a Profile: a fixed image, CPU and memory size. The workflow never names a machine; EraInfra picks one that is ready for that Profile.

What works today

PlatformExecutorIsolation
Linux x64 and ARM64FirecrackerOwn guest kernel per job. Use this for untrusted code. Needs KVM.
Linux x64 and ARM64DockerShares the host kernel. Only for jobs that trust each other.
Apple Silicon macOSTartCopy-on-write VM per job, two at a time by default.
Windows x64Hyper-VOne job at a time. The machine is offered work only after it proves Hyper-V works.
  • Each job's environment is removed on every exit path, including a Worker crash, and its GitHub credentials are single-use.
  • Each Worker checks its own isolation. A Worker whose live firewall rules drift from the rendered policy stops taking jobs.
  • A Profile can deny all outbound traffic except an allowlist of domains and address ranges, or record what its jobs reach first.
  • An optional router job sends a run to GitHub-hosted runners when no machine of yours is free.
  • A job cache that serves actions/cache, setup-node and setup-go from your own storage on Firecracker Profiles.
  • The same machines can also run long-lived apps. A Hub builds and deploys them on git push and serves each one at its own HTTPS address.

The project's own fleet has run its Linux jobs in Firecracker microVMs since 20 August 2026.

How it compares

Instead of EraInfraChoose it whenWhere EraInfra differs
GitHub-hosted runners You want nothing to operate. Runs on hardware you already have, and can send a run to GitHub-hosted runners when your machines are busy.
A plain self-hosted runner You have one trusted repository and one machine. A plain runner reuses the same host between jobs. EraInfra prepares an environment for one job and removes it afterwards.
Actions Runner Controller Your whole fleet already runs Kubernetes. It is the better choice there. Targets machines without a cluster, including Macs and machines behind NAT or a home router.
Fireactions You only need Firecracker runners on Linux. EraInfra uses Fireactions as the reference for its Linux executor, and puts Linux, macOS and Windows machines under one scheduler.

Limits

  • The control plane, scheduler and dashboard run on Convex, so you need a Convex deployment.
  • Firecracker Workers need KVM and dedicated runtime storage.
  • macOS Workers run at most two VMs by default, to stay within Apple's virtualization license.
  • Self-hosted runners run repository code with that repository's token and secrets. Keep Profiles private to trusted repositories, and do not run pull requests from untrusted forks on machines that hold persistent credentials.
  • The app Hub is a second control plane, separate from the Convex one, and needs a Cloudflare Tunnel for its HTTPS addresses.
  • Version 0.2 is still in release candidates.

Get started

  1. Deploy the Convex backend and dashboard from the repository.
  2. In the dashboard, open Machines, choose Add machine, and run the generated install command on each host.
  3. Point a workflow at a Profile with runs-on.
