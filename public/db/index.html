EraDB

EraDB is a local-first application database for TypeScript apps. Your app reads from durable storage on the device and shows a command's predicted result at once. PostgreSQL stays the source of truth, and every query result says whether the local data is complete.

Who it is for

App developers who want a typed, realtime backend in the style of Convex, running on their own PostgreSQL instead of a hosted service, with reads that do not wait for the network.

What works today

  • A typed schema with queries, commands, access policies and migrations. Commands are compiled at build time and verified by a separate checker, so the same command runs on the device for the prediction and on the server for the real write.
  • A local client that shows a command's predicted result, then settles it against the server's answer.
  • A durable browser Worker on SQLite that keeps one leader across open tabs.
  • PostgreSQL as the authority, with change data capture and ordered WebSocket sync.
  • Server functions, scheduling, file storage, search and authentication.
  • Bindings for React, Vue, Svelte, Next.js and TanStack Query, and clients for Rust, Python, Kotlin and Swift.
  • A CLI, a dashboard, and a self-host control plane with encrypted secrets, an audit log, and backup and restore.

How finished it is

EraDB scores itself against a list of 190 Convex capabilities. Each one passes only when a tagged test proves it. At the last recorded run, 189 passed. The one failure is a process check: the published scorecard was too old. Three serious findings from adversarial review are also open, so the verdict is a fail.

PostgreSQL with your own API Your app can wait for the network on every read and does not need live updates. Sync, local caching, predicted results and policy checks on the server are included, so you do not build them yourself.

Limits

  • None of the 22 packages is on npm. You build signed tarballs from a checkout and install them by hand.
  • The source is not public yet.
  • There is no hosted service. Self-hosting needs a control-plane image you build yourself and a PostgreSQL database.
  • Writes have hard limits. For example, one command writes at most 8,192 rows, and function arguments are capped at 8 MiB.
