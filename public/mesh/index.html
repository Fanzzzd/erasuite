EraMesh

EraMesh is a private mesh network for your own computers, phones and servers. You choose the order of exit devices, relays are always your own machines, and traffic moves to QUIC over TCP when a network blocks UDP.

Who it is for

People who run their own servers and want their computers and phones to send traffic out through those servers, with control over which server comes first and what happens when it goes down.

What works today

  • Devices join by one-time invite. Members can take the exit, relay or admin role, and a removed device cannot come back with an old member list.
  • A ranked list of exits. New connections use the highest healthy exit, a failed exit is replaced within 3 seconds, and an empty or fully failed list stops traffic instead of sending it out directly.
  • Three kinds of path in one connection: direct UDP, UDP relayed by one of your members, and QUIC carried over TCP when a network blocks UDP.
  • Member connections use TLS 1.3 with the hybrid post-quantum key exchange X25519MLKEM768 only. A peer that cannot use it fails the handshake.
  • The fp command-line tool: SOCKS5 and HTTP proxy, application UDP, a DNS stub that resolves through the exit, static port forwards, and a proxy list for Clash and mihomo.
  • A full-device tunnel on Linux and macOS that blocks traffic when no exit is healthy. On Windows it runs only in the lab VM so far.
  • In the Linux lab, every network fault passed 3 of 3 runs, including UDP block, a 5-second blackout, address change and exit loss. 900 of 900 fresh connections succeeded at 50 to 250 ms round-trip time and up to 10% loss.
  • Desktop, Android, iPhone and Apple TV apps share one Rust core instead of reimplementing it.

Platform evidence

A platform counts as supported only after its app completes the shared acceptance flows on a recorded OS version. The Linux and Android runners have passed every flow they require. No platform has passed the full product bar yet, which also needs a 24-hour soak, the full fault matrix and a performance comparison on one frozen commit.

How it compares

Instead of EraMeshChoose it whenWhere EraMesh differs
Tailscale You want a private network that works today on every major platform, with signed apps, admin tools and support. It is mature, and it is the better choice now. No coordination service to depend on, relays only through your own members, and failover through an exit list you rank.
Headscale with Tailscale clients You want Tailscale's mature clients with a coordination server you host yourself. You run no server. The admin device holds the network key, and members share the signed member list among themselves.
WireGuard You want a small, fast tunnel between machines you configure by hand. It is in the Linux kernel and has clients everywhere. Adds invites, roles, exit failover, member relays and QUIC over TCP when UDP is blocked.
ZeroTier or Nebula You want every device to get an address on a virtual network, with NAT traversal, proven at scale. Focuses on exits: a ranked list that fails closed. It gives devices no addresses and does no NAT traversal yet.
Hysteria 2 You need one fast proxy from one client to one server. A network of member devices with invites, relays and exit failover. The project's lab runs both under the same network conditions, and that comparison is not finished.

Limits

  • No release, no packages and no signed apps. The source is not public yet.
  • No platform has passed the full product bar: the 24-hour soak, the full fault matrix and the performance comparison are not done.
  • Devices get no network addresses of their own, so you cannot reach another member by address. Traffic goes from a device out through an exit.
  • No NAT traversal yet. A device connects only to members it can reach directly, or through a relay member both sides can reach.
  • Only the admin that created the network can redeem invites, so it must be online when a device joins.
  • When an exit fails, open TCP connections through it reset. New connections use the next exit.
  • The Windows full tunnel refuses to start outside the lab VM. iPhone and Apple TV have no device runs yet.
